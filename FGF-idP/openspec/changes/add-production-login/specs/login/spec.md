## ADDED Requirements
### Requirement: Production login page
The service SHALL serve a responsive forest/glass login page and local assets from its Go executable without a frontend runtime.
#### Scenario: Valid authorization request
- **WHEN** a user visits /login with req_id
- **THEN** the page SHALL accept account or email and password and submit only to the same-origin login API.
#### Scenario: Missing authorization request
- **WHEN** req_id is missing
- **THEN** the page SHALL explain that login must start from the originating service and SHALL NOT submit credentials.
### Requirement: Compatible authentication flow
The service SHALL preserve existing OAuth redirects and API error responses while supporting the production browser UI.
#### Scenario: JSON login
- **WHEN** a successful POST /x/login explicitly accepts application/json
- **THEN** it SHALL return 200 with redirect_to generated by the server; other clients SHALL retain 302 behavior.
#### Scenario: Device verification
- **WHEN** login returns 203
- **THEN** the page SHALL show a masked email and instruct the user to open the verification link in the same browser without polling, resend or trust options.
#### Scenario: Invalid verification link
- **WHEN** a browser requests an invalid /x/verify link
- **THEN** it SHALL be directed to a friendly login error state while API clients retain JSON errors.
